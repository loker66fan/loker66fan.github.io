# 学习日志

## 主题

本轮围绕“用 Vue 改造静态导航页”展开，主要学习和实践了页面状态管理、可滚动布局设计、第三方组件整合以及交互细节排查。

## 1. 对 Vue 在静态项目中的使用有了更清晰的认识

以前这类主页更容易用 jQuery 或直接操作 DOM 的方式堆出来，但随着功能变多，状态会越来越散。把首页改成 Vue 驱动后，明显感觉到下面几点更清晰：

- 搜索框开关、更多面板、音乐弹窗都可以直接用响应式状态描述
- 模板和数据结构之间的关系更直接
- 后面再删模块或增模块时，改动范围更容易控制

这说明即使不使用 Vite 或单文件组件，Vue 全局版本在小型静态项目里依然很有价值。

## 2. 学到“整屏展示”和“可滚动页面”是两套不同布局思路

这次最典型的问题是：

- 一开始页面用了 `overflow: hidden`
- `section` 和若干层用了固定定位、缩放和模糊动画
- 看起来很像一张整屏展示海报

但一旦内容变多，这种布局会立刻出现问题：

- 页面无法下滑
- 内容容易互相挤压
- footer 会挡住内容

这次的修复让我更明确：

- 如果页面内容会增长，就应该优先使用文档流布局
- 固定定位更适合背景层、悬浮按钮、弹窗，而不是整个页面主体

## 3. 认识到 transform 会影响 fixed 元素的定位参照

鼠标特效偏移问题非常有代表性。

一开始看起来代码没问题：

- 鼠标位置用的是 `clientX/clientY`
- 光标元素也改成了 `position: fixed`

但它还是偏移。真正原因是：

- 鼠标元素放在了带 `transform` 的父容器里面
- 这会改变 `fixed` 的参考系

这次排查让我记住一个很实用的点：

- 只要元素需要绝对贴合视口，就要避免让它处在带 `transform`、`filter`、`perspective` 等效果的父层里

## 4. 删除功能比继续堆功能更重要

这次用户明确要求删掉：

- `workspace-overview cards`
- `status-card cards`

删完后页面其实更清楚了。这个过程让我意识到：

- 页面不是模块越多越好
- 不是每个状态都值得被可视化成卡片
- 多余的信息只会破坏层级和节奏

开发时要更关注“哪些内容真的有必要长期占位”。

## 5. 样式统一比单个组件精致更重要

本轮左栏观感不好的根本原因不是某一块难看，而是：

- 左栏宽度和右栏不在同一节奏上
- 卡片的内边距、最大宽度、对齐线不一致
- 有些块像面板，有些块像散落的组件

后面通过统一：

- 列宽
- 卡片内边距
- 按钮排布方式
- 模块宽度基线

页面一下就整齐很多。这个结果说明在首页设计里，统一节奏比局部花哨更关键。

## 6. 对个人项目文档化的重要性有更直接的感受

这个项目之前几乎没有成体系的中文文档，后续一旦继续改：

- 很难快速回忆模块职责
- 很难知道最近到底改了什么
- 很难沉淀真正学到的知识

所以这次补技术文档、开发日志和学习日志，不只是“补材料”，本质上是在建立项目的演进记录。
